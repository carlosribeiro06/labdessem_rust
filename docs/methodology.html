Methodology

LabDessem Rust implements a hydrothermal scheduling model with thermal unit commitment, hydro operation with cascades, and optional network representation.

Model Scope

The current model supports:

  • Thermal unit commitment with startup and shutdown trajectories
  • Minimum up/down time for thermal units
  • Thermal residual TON cost treatment at horizon end
  • Hydro scheduling with cascades, water diversion, pumping plants
  • Two hydro generation formulations (FPHA cuts or productivity)
  • Dynamic maximum swallowing (EngMax) based on net head
  • Future cost function via Benders cuts
  • Generic renewable plants bounded by programmed generation
  • Submarket demand balance with optional DC network
  • Operational limit constraints

Objective Function

The objective minimizes total operational cost:

min Σ (thermal generation cost + startup cost + shutdown cost)
    + Σ (hydro spillage cost + turbining cost)
    + Σ (interchange penalty)
    + future cost (when FCF=1)

Thermal Unit Commitment

When UCT=1, each thermal unit has binary variables:

  • u[i,t] — commitment status (on/off)
  • v[i,t] — startup indicator
  • w[i,t] — shutdown indicator

Constraints enforce:

u[i,t] - u[i,t-1] = v[i,t] - w[i,t]  (state transition)
Σ u[i,τ] ≥ min_up_time × v[i,t]       (minimum up time)
Σ (1-u[i,τ]) ≥ min_down_time × w[i,t] (minimum down time)

Ramp Trajectories

Thermal units follow predefined ramp trajectories during startup and shutdown. The model reads trajectories from CAD_RAMPAS_TERMICAS.csv and enforces generation to follow the trajectory during state transitions.

Hydraulic Balance

For each hydro plant and period:

V[i,t] = V[i,t-1] + A[i,t] - Q[i,t] - S[i,t] + Σ(Q[j,t] + S[j,t]) - W[i,t]

Where:

  • V — reservoir volume
  • A — natural inflow
  • Q — turbining
  • S — spillage
  • W — water withdrawal
  • Summation over upstream plants in the cascade

FPHA Formulation

The Hydro Production Function Approximation (FPHA) linearizes the nonlinear relationship between generation, head, and turbining.

When FPHA="precomputed" or "computed", generation is bounded by piecewise linear cuts:

G[i,t] ≤ α₀ + α₁×V[i,t] + α₂×Q[i,t] + α₃×Qlat[i,t]

Cuts are read from OPER_FPHA.csv (precomputed) or computed at runtime from VHA geometry (computed).

When FPHA="constant_productivity", generation is computed directly:

G[i,t] = ρ × Q[i,t]

Where ρ is the specific productivity (MW per m³/s).

Dynamic Maximum Swallowing (EngMax)

When EngMax=1, the maximum turbining of each hydro unit is adjusted dynamically based on the net head:

Q_max[i,t] = Q_ef × (h_l / h_ef)^α

Where:

  • Q_ef — maximum turbining at effective head (from registration)
  • h_ef — effective head (from registration)
  • h_l — net head calculated from reservoir volume
  • α — turbine exponent (0.5 for Francis, 0.2 for Kaplan)

Net head is calculated as:

h_l = forebay_level(V) - tailrace_level(Q) - hydraulic_loss

The forebay level is interpolated from the VHA table (CAD_GEOMETRIA_UHE.csv), and the tailrace level is computed from a 4th-degree polynomial (CAD_TAILRACE.csv):

tailrace = a₀ + a₁×Q + a₂×Q² + a₃×Q³ + a₄×Q⁴

EngMax constraints coexist with static turbining limits. When the net head is lower than the effective head, EngMax reduces the turbining limit. When geometry data is unavailable, the effective head from registration is used.

Bounds are recalculated between solve stages using the reservoir volumes from the previous solution.

Future Cost Function

The Future Cost Function (FCF) represents the expected cost-to-go from the end of the horizon. It is approximated by Benders cuts:

α ≥ π₀ + Σ πᵢ × Vfinal[i]

Where:

  • α — future cost variable (added to objective)
  • π₀ — cut intercept
  • πᵢ — coefficient for final volume of hydro plant i

Cuts are read from binary file OPER_FCF.bin when FCF=1.

DC Network Flow

When rede=1, the model includes DC power flow approximation:

f[l,t] = (θ[from] - θ[to]) / x[l]  (line flow)
|f[l,t]| ≤ f_max[l]                 (thermal limit)

Bus power balance enforces generation minus demand equals net injection.

Iterative Network Cuts

In execution mode 1, network constraints are added iteratively:

  1. Solve LP relaxation (network-free)
  2. Compute DC flows from solution
  3. Identify violated line-period pairs
  4. Add flow constraints for violations
  5. Repeat until no violations or iteration limit
  6. Solve final MILP with all cuts
  7. Fix integers and solve LP-CALC-CMO for duals

This approach keeps the model size manageable while ensuring feasibility.
