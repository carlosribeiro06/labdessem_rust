# Network Cuts

This document describes the DC network flow model and cut generation in labdessem.

## Overview

When `rede = 1` in `study_config.json`, labdessem computes DC power flows and adds linear constraints to enforce transmission line limits. The network model uses the Power Transfer Distribution Factor (PTDF) matrix to express line flows as linear functions of bus injections.

## DC Power Flow Model

### Assumptions

The DC power flow model makes standard assumptions:

1. Voltage magnitudes are 1.0 p.u. at all buses
2. Phase angle differences are small (sin(θ) ≈ θ)
3. Line resistances are negligible (R << X)
4. No reactive power flow

### PTDF Matrix

The PTDF matrix relates line flows to bus injections:

```
flow[line] = Σ(PTDF[line, bus] × injection[bus])
```

Where `injection[bus] = generation[bus] - demand[bus]`.

The PTDF is computed from:

```
PTDF = diag(1/X) × A × B⁻¹
```

Where:
- `X` = vector of line reactances
- `A` = branch-bus incidence matrix
- `B` = susceptance matrix (with slack bus row/column removed)

## Flow Constraint Generation

### Constraint Form

For each (line, period) pair, two constraints enforce the line limit:

```
-limit ≤ Σ(PTDF[line, bus] × (generation - demand)[bus]) ≤ limit
```

This is implemented as two inequality constraints:
- Upper bound: `Σ(...) ≤ limit`
- Lower bound: `-Σ(...) ≤ limit` (equivalently: `Σ(...) ≥ -limit`)

### Iterative Addition

In mode 1 (iterative), constraints are added incrementally:

1. Solve LP without network constraints
2. Compute flows using PTDF × injections
3. Identify lines where |flow| > limit (violations)
4. Add constraints only for violated (line, period) pairs
5. Re-solve and repeat until no violations

This iterative approach is more efficient than adding all constraints upfront, especially for large networks with few binding lines.

### Single-Shot Addition

In mode 2 (single MILP) with network enabled, all line constraints are added initially to ensure the MILP solution respects all limits.

## Network Slack Variables

When a flow violation cannot be eliminated (e.g., insufficient generation capacity), the model introduces slack variables with a high penalty cost:

```
flow + slack_plus - slack_minus ≤ limit
objective += penalty × (slack_plus + slack_minus)
```

The penalty cost is set high (1,000,000 R$/MW) to ensure slacks are only used when necessary, making the solution infeasible-indicating rather than silently violating limits.

## Implementation Details

### DcNetworkModel

The `DcNetworkModel` struct contains:

- `ptdf_rows`: PTDF matrix (one row per branch)
- `non_slack_bus_ids`: Bus IDs used in PTDF computation
- `branch_limits`: Thermal limits per branch

### Flow Terms

For each cut, the flow terms are generated by:

```rust
fn flow_terms_for_cut(
    system: &System,
    dc_network: &DcNetworkModel,
    indexing: &Indexing,
    variables: &Variables,
    branch_idx: usize,
    period: usize,
) -> Vec<LinearTerm>
```

This function iterates over all generation sources at each bus and multiplies by the corresponding PTDF entry.
