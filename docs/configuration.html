Configuration

Each study case requires a study_config.json file in its root directory. This file controls execution mode, model features, and solver behavior.

study_config.json

Example configuration:

{
  "$schema": "../../schemas/study_config.schema.json",
  "opcao_execucao": 2,
  "rede": 0,
  "UCT": 1,
  "UCH": 0,
  "TON_Residual": 0,
  "FPHA": "constant_productivity",
  "FCF": 1,
  "EngMax": 0
}

JSON Schema

A JSON Schema is provided at schemas/study_config.schema.json for IDE autocompletion and validation.

Add the $schema property to your config file:

{
  "$schema": "../../schemas/study_config.schema.json",
  ...
}

The schema path is relative to your study directory. Adjust the path based on your directory structure.

IDE Setup

VS Code

For automatic validation across all study configs, add to .vscode/settings.json:

{
  "json.schemas": [
    {
      "fileMatch": ["**/study_config.json"],
      "url": "./schemas/study_config.schema.json"
    }
  ]
}

Execution Mode

Value Description
1 Iterative: LP → MILP → LP-FIXED → LP-CALC-CMO
2 Single MILP solve

Mode 1 (Iterative): Starts with LP relaxation, solves MILP, then fixes integers and re-solves for dual information (CMOs). When network is enabled, adds DC flow cuts iteratively for violated line-period pairs.

Mode 2 (Single MILP): Direct mixed-integer solve. Faster but no dual information extraction.

Model Flags

Flag Type Description
rede 0/1 Enable DC network flow representation
UCT 0/1 Enable thermal unit commitment (binary variables)
UCH 0/1 Enable hydro unit commitment (binary variables)
TON_Residual 0/1 Enable thermal residual TON treatment at horizon end
FPHA string Hydro generation formulation: "constant_productivity", "precomputed", or "computed"
FCF 0/1 Enable future cost function (Benders cuts from OPER_FCF.bin)
EngMax 0/1 Enable dynamic maximum swallowing constraint (head-dependent turbining limits)

FPHA Flag

Controls how hydro generation is computed. FPHA takes one of three strings. A number, such as the earlier 0 and 1 values, makes study_config.json fail to parse.

Value Hydro generation Files read
"constant_productivity" Generation = productivity × turbining. Simpler but less accurate for varying head. Prod.mw/m3s of CAD/CAD_UHE.csv
"precomputed" Generation bounded by the piecewise linear planes of OPER_FPHA.csv. OPER/OPER_FPHA.csv
"computed" Generation bounded by planes fitted at run time to the production function of each hydro plant. The constraint rows are the same as in "precomputed". The planes are written to RESULTADOS/resultado_fpha_computed.csv; OPER_FPHA.csv is not read. Required for every hydro plant with generating units:
  • CAD/CAD_GEOMETRIA_UHE.csv
  • CAD/CAD_TAILRACE.csv
  • Eficiencia and Perda.m of CAD/CAD_UHE.csv. An explicit Perda.m = 0 is valid; an absent column or an empty cell counts as missing.
Optional:
  • CAD/CAD_FPHA_CONFIG.csv (see below)
  • OPER/inflow_history.parquet: its plant mean is the long-term mean inflow that sets the spillage range of the fit. Without the file the fit uses the mean of the deck inflows and the CLI prints Warning: inflow_history.parquet not found; using deck mean for MLT. With the file, a plant it lacks stops the run with missing from inflow_history.parquet.

Computed mode fits only hydro plants with generating units (CAD_CONJ_UHE.csv). A plant without units is not fitted and needs none of the inputs above. If any plant with units cannot be fitted, the run stops before writing any result (see Computed FPHA failures). The formulation is in Methodology.

CAD_FPHA_CONFIG.csv

CAD/CAD_FPHA_CONFIG.csv is optional and read only when FPHA="computed". It overrides the fit of single plants: a ;-delimited file with a header line and one row per plant. A plant without a row, or a study without the file, uses the defaults.

Column Accepted header aliases Meaning Unit Default
codigo_usina Codigo, CODIGO, codigo Plant code of CAD_UHE.csv. Required in every row. plant code none
num_planes MaxPlanes, max_planes Plane limit: the most planes kept for the plant. An integer of at least 1. planes 10
tolerance ReductionTolerance, Tolerance Starting angle tolerance for merging planes with nearly parallel normals. Not negative. degrees 1.0
min_volume_pct MinVolumePct Lower bound of the fit volume window. fraction in [0, 1] of the CAD_UHE.csv [Vmin, Vmax] interval 0
max_volume_pct MaxVolumePct Upper bound of the fit volume window. fraction in [0, 1] of the CAD_UHE.csv [Vmin, Vmax] interval 1

Example file with one row:

codigo_usina;num_planes;tolerance;min_volume_pct;max_volume_pct
0;6;2.0;;0.9

This row sets, for plant 0, a limit of 6 planes, a starting angle tolerance of 2.0 degrees and a window that ends at 90% of the [Vmin, Vmax] interval. The empty min_volume_pct cell keeps its default of 0.

  • Empty cell: an empty cell keeps the default of its column. A column missing from the header keeps the default for every plant.
  • Window: despite the _pct suffix, the bounds are fractions, not percentages. The window is [Vmin + min_volume_pct × span, Vmax − (1 − max_volume_pct) × span] with span = Vmax − Vmin, both from CAD_UHE.csv (Vmin.hm3, Vmax.hm3), not from the geometry table. The window must lie inside the volume range of the plant in CAD_GEOMETRIA_UHE.csv, and min_volume_pct must be below max_volume_pct; otherwise the plant cannot be fitted. A plant whose geometry table has a single point ignores the window.
  • Plane limit: a labdessem extension, not DESSEM behavior. The fit merges planes with the angle tolerance and, while more planes than the limit remain, doubles the tolerance and merges again. A limit the merging cannot reach fails the plant.
  • Defaults without the file: at most 10 planes, an angle tolerance of 1.0 degree and a window over the whole [Vmin, Vmax] interval. The fit samples a 5 × 5 volume-flow grid; the grid is not configurable.
  • Rejected rows: a negative tolerance, a window bound outside [0, 1], num_planes 0, min_volume_pct not below max_volume_pct, a non-finite value and a second row for the same plant stop the run (see below).

Computed FPHA failures

A failure prints Error: <message> on stderr and exits with code 1 before any result is written. A message found while reading CAD_FPHA_CONFIG.csv in computed mode carries the extra prefix I/O error:; a message found while reading the study (CAD_GEOMETRIA_UHE.csv, CAD_TAILRACE.csv, OPER_FPHA.csv) does not. The table quotes the fixed part of each message. Text in angle brackets, such as <n> or <name>, stands for a value the run fills in.

Message fragment Meaning How to fix the deck
computed FPHA could not be fitted for The full text is computed FPHA could not be fitted for <n> hydro plant(s) with generating units:, followed by one line plant <id> (<name>): <reason> for every plant with units that could not be fitted. The reason is one of:
  • no rows in CAD/CAD_GEOMETRIA_UHE.csv
  • missing inputs: followed by row in CAD/CAD_TAILRACE.csv, Eficiencia in CAD/CAD_UHE.csv (column absent or empty) or Perda.m in CAD/CAD_UHE.csv (column absent or empty), or several of them
  • invalid fit parameters: and the detail
  • fitting failed: and the detail of the fit, for example cannot reduce to below
 Fix every plant listed, not only the first. Add the geometry rows or the missing input named in the line. A plant without generating units needs none of them.
system validation failed after FPHA injection: After the fitted planes are injected, the whole system is validated again with FPHA on. The text after the colon names the violated rule, for example a plant with generating units that ended with no FPHA segment. Correct the item named after the colon.
cannot reduce to The full text is hydro <name>: cannot reduce to <n> planes (<k> remain after the last tolerance), shown as a fitting failed: reason. Merging planes with a doubled tolerance, at most 32 times, did not reach the plane limit. Raise num_planes or tolerance of that plant in CAD_FPHA_CONFIG.csv.
has a single-point table in CAD/CAD_GEOMETRIA_UHE.csv A Warning:, not an error; the fit continues. The plant has one point in its geometry table, so the min_volume_pct and max_volume_pct of its CAD_FPHA_CONFIG.csv row are ignored. An unset bound prints unset. Delete the window bounds of that row to silence the warning.
OPER_FPHA.csv has FPHA rows for hydro plant(s) without generating units in Precomputed mode. The full text continues with CAD_CONJ_UHE.csv: <code> (<name>), ... and lists every affected plant in ascending code order. Delete the OPER_FPHA.csv rows of the listed plants, or add their generating units to CAD_CONJ_UHE.csv.
has non-finite The full text is plant <id> has non-finite <column> <value> at line <n> in <file>. A cell of CAD_GEOMETRIA_UHE.csv, CAD_TAILRACE.csv or CAD_FPHA_CONFIG.csv holds NaN, inf or -inf. Replace the cell at the line named with a finite value.
has duplicate rows at lines The full text is plant <id> has duplicate rows at lines <a> and <b> in <file>. CAD_TAILRACE.csv and CAD_FPHA_CONFIG.csv take one row per plant. In CAD_GEOMETRIA_UHE.csv the same check reads has duplicate volume: two points of one plant share a volume.hm3. Delete the repeated row or point.
has num_planes 0 (must be at least 1) The full text is plant <id> has num_planes 0 (must be at least 1) at line <n> in CAD_FPHA_CONFIG.csv. The plane limit cannot be 0. Set num_planes to 1 or more, or leave the cell empty for the default of 10.

The design behind these policies, with the decision records, is in docs/design/fpha-formulation.md.

FCF Flag

Controls future cost function:

  • FCF=1: Read Benders cuts from OPER_FCF.bin. Adds future cost variable and constraints linking final storage to expected future cost.
  • FCF=0: No future cost. Useful for deterministic single-stage studies.

EngMax Flag

Controls dynamic maximum swallowing (head-dependent turbining limits):

  • EngMax=1: Bound each hydro plant's total turbining by its head-dependent maximum swallowing, recalculated after every solve. See Methodology for the formula.
  • EngMax=0: Use static maximum turbining from registration data.

When geometry data is not available for a plant, EngMax falls back to the effective head from registration.
