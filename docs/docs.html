Documentation

LabDessem Rust is a modular workspace for hydrothermal scheduling optimization. This guide covers installation, basic usage, and workspace organization.

Installation

Clone the repository and install the CLI:

git clone https://github.com/carlosribeiro06/labdessem_rust.git
cd labdessem_rust
cargo install --path crates/labdessem-cli

This installs the labdessem binary to ~/.cargo/bin/.

Requirements

  • Rust 1.70 or later
  • CMake (for HiGHS solver compilation)
  • C++ compiler (Visual Studio Build Tools on Windows, GCC/Clang on Linux)

Quick Start

Run an example study case:

labdessem run examples/24Barras

Results are written to examples/24Barras/RESULTADOS/.

CLI Usage

# Run a study case (path argument)
labdessem run examples/24Barras

# Run from the case directory
cd examples/24Barras
labdessem run

# Show help
labdessem --help
labdessem run --help

Workspace Structure

labdessem_rust/
├── crates/
│   ├── labdessem-cli        # Command-line interface
│   ├── labdessem-core       # Domain entities, IDs, validation
│   ├── labdessem-io         # Case reader and output writers
│   ├── labdessem-model      # Variables, objective, constraints
│   ├── labdessem-simulation # Workflow orchestration
│   └── labdessem-solver     # Optimization backend (HiGHS)
├── docs/                    # This website
├── examples/                # Example study cases
├── schemas/                 # JSON Schema for study_config.json
└── Cargo.toml               # Workspace configuration

Crates

Crate Description
labdessem-cli Command-line interface. Produces the labdessem binary.
labdessem-core Domain entities, identifiers, validations, horizon representation.
labdessem-io Case reader. Loads study_config.json and CSV files from CAD/ and OPER/.
labdessem-model Indexing, variables, objective function, and algebraic constraints.
labdessem-solver Optimization backend integration through good_lp with HiGHS.
labdessem-simulation End-to-end orchestration: solve workflow, network iterations, output export.

Input Data

Each study directory is organized with:

  • study_config.json — Study configuration (see Configuration)
  • CAD/ — Static registration data (plants, buses, lines)
  • OPER/ — Time-varying data (demand, inflows, availability)

CAD Files (Registration)

  • CAD_UNID_UTE.csv — Thermal plants and units
  • CAD_RAMPAS_TERMICAS.csv — Thermal ramp trajectories
  • CAD_UHE.csv — Hydro plants
  • CAD_CONJ_UHE.csv — Hydro groups and units
  • CAD_REN.csv — Renewable plants
  • CAD_USIE.csv — Pumping plants

OPER Files (Operational)

  • OPER_SBM.csv — Submarket demand
  • OPER_VAZAO.csv — Hydro inflows
  • OPER_REN.csv — Renewable availability
  • OPER_REST_LIM.csv — Operational limits
  • OPER_FPHA.csv — FPHA cuts (when FPHA=1)
  • OPER_FCF.bin — Future cost cuts (when FCF=1)

Outputs

After a successful run, CSV files are written to RESULTADOS/:

  • resultado_termicas.csv — Thermal generation and commitment
  • resultado_hidreletricas.csv — Hydro generation, turbining, spillage
  • resultado_renovaveis.csv — Renewable generation
  • resultado_elevatorias.csv — Pumping plant operation
  • resultado_cmosist.csv — Marginal operating costs (PiDemanda and CMO)
  • resultado_fcf_eco.csv — Future cost cut values (when FCF=1)
  • resultado_rede.csv — Network flows (when rede=1)
  • resultado_cmobar.csv — Nodal marginal costs per bus (when rede=1)
